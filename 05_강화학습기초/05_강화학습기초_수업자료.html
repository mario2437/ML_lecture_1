PART 1오늘 배우는 것 — 강화학습 개념 정리

강화학습(Reinforcement Learning)은 정답을 알려 주지 않고 행동의 결과에 점수(보상)만 주면서 스스로 좋은 행동을 찾게 하는 학습 방식입니다. 강아지 훈련, 게임 AI, 알파고, 로봇, ChatGPT의 답변 다듬기(RLHF)가 모두 이 원리를 씁니다.

1-1. 지도학습·비지도학습과 무엇이 다른가

지도학습 (2·3회차)비지도학습 (4회차)강화학습 (오늘)
무엇이 주어지나입력 + 정답입력만입력 + 행동의 결과 점수(보상)
무엇을 배우나입력→정답 규칙데이터의 숨은 구조(군집)점수를 많이 받는 행동 규칙(정책)
데이터는 어디서미리 모아 둔 표미리 모아 둔 표직접 행동하며 만들어 냄
예시사진 → 고양이/개고객을 3그룹으로게임 이기기 · 로봇 걷기 · 추천

지도학습이 "선생님이 답을 알려 주는 공부"라면, 강화학습은 "게임을 하면서 점수로 배우는 공부"입니다. 바둑의 다음 수처럼 정답을 미리 적어 둘 수 없는 문제에 강화학습을 씁니다.

1-2. 강아지는 어떻게 "앉아"를 배울까

  • 강아지가 이것저것 해 본다(짖기·눕기·앉기…) → 우연히 앉았을 때 간식(보상)을 준다 → "앉으면 좋은 일이 생긴다"를 기억한다 → 앉는 행동이 점점 자주 나온다.
  • 정답 동작을 보여 주지 않는다는 점, 처음엔 아무렇게나 해 본다는 점, 좋았던 행동을 더 자주 하게 된다는 점이 강화학습의 세 가지 특징입니다. 이것을 시행착오(trial and error) 학습이라고 합니다.

1-3. 여섯 가지 용어 — 에이전트·환경·상태·행동·보상·정책

용어뜻5×5 미로에서는
에이전트 (agent)배우는 주체미로 속 캐릭터
환경 (environment)에이전트가 사는 세상5×5 칸의 미로, 함정, 목표
상태 (state)지금 상황지금 있는 칸의 좌표 (행, 열) — 25가지
행동 (action)고를 수 있는 선택↑ ↓ ← → 네 가지 (벽 쪽이면 제자리)
보상 (reward)행동 직후 받는 점수목표 +10, 함정 ?, 한 걸음 ? (오늘 여러분이 설계)
정책 (policy)"어떤 상태에서 어떤 행동을 할지"의 규칙 — 배우는 것25개 칸마다 어느 방향 → 화살표 지도
에피소드 (episode)게임 한 판시작 → 목표·함정에 닿거나 50걸음이면 끝
목표는 "한 판의 총 보상"을 크게 하는 것한 번의 점수가 아니라 한 판 동안 받는 보상의 합을 크게 만드는 정책을 찾습니다. 지금 당장 −1이어도 나중에 +10이면 좋은 선택입니다. 그래서 "미래의 보상을 얼마나 중요하게 볼지"를 정하는 할인율 γ가 필요합니다.

1-4. 배우지 않은 에이전트는 어떻게 될까

무작위로 100판을 하면 성공률은 2%입니다(실습 셀 3에서 확인). 학습 후에는 8걸음(최단) 경로로 도착합니다. 둘의 차이는 경험을 점수표에 기록했는가뿐입니다. 그 점수표가 다음의 Q-table입니다.

1-5. 탐험(explore) vs 활용(exploit)

  • 늘 가던 식당(활용)만 가면 더 맛있는 집(탐험)을 영영 모릅니다. 그래서 ε(입실론)의 확률로는 일부러 아무 행동이나 해 봅니다. 이 규칙을 ε-greedy라고 합니다.
  • ε = 0.2 → 10번 중 2번은 무작위, 8번은 점수표에서 최고 점수 행동.
  • ε이 너무 작으면 처음 찾은 길에 갇히고, 너무 크면 배운 뒤에도 자꾸 헤맵니다. 실습 "직접 해보기 2"에서 직접 비교합니다.

1-6. Q-table — "이 행동을 하면 앞으로 얼마나 좋을까" 점수표

  • 크기: 25칸 × 4행동 = 100개의 숫자. 처음엔 전부 0. 코드로는 Q = np.zeros((5, 5, 4)) 한 줄.
  • 학습 = 경험할 때마다 이 숫자를 조금씩 고치는 것. 다 배운 뒤엔 칸마다 가장 큰 값의 행동을 고르면 됩니다.
  • "Q"는 행동의 질(Quality)이라는 뜻입니다.

1-7. Q-learning 갱신 규칙 — 딱 한 줄

갱신식
Q(s, a) ← Q(s, a) + α · [ r + γ · max Q(s′, ·) − Q(s, a) ]
말로 풀면: "지금 적힌 점수를 → (방금 받은 보상 + 다음 칸에서 기대되는 최고 점수) 쪽으로 α만큼 옮긴다." 목표·함정처럼 게임이 끝나는 칸에 도착했으면 다음 칸이 없으므로 보상 r만 씁니다.
기호이름뜻오늘 값바꾸면?
α (알파)학습률한 번에 얼마나 크게 고칠까 (0~1)0.1크면 빨리 배우지만 들쭉날쭉, 작으면 느리지만 안정
γ (감마)할인율미래 보상을 얼마나 중요하게 볼까0.91에 가까울수록 멀리 봄, 0에 가까우면 눈앞 보상만
ε (입실론)탐험 확률얼마나 자주 모험할까0.2크면 많이 헤매고, 0이면 처음 길에 갇힘

1-8. 보상 설계가 행동을 바꾼다 — 그리고 보상 해킹

설계목표함정한 걸음결과해석
① 목표만+10008걸음 도착함정에 벌은 없지만 게임이 끝나므로 피하긴 함
② 함정 벌점+10−1008걸음 도착함정 옆을 덜 지나는 벽 쪽 길을 고르는 경향
③ + 걸음 비용+10−10−0.18걸음 도착오래 헤매면 손해 → 짧은 길 선호
④ 함정에 상+10+503걸음 함정행보상 해킹 — 적힌 점수만 최대화
보상 해킹(reward hacking) 실제 사례
  • 보트 경주 게임: 결승선 대신 코스 중간의 점수 아이템만 빙빙 돌며 먹음.
  • 청소 로봇: "쓰레기를 보면 벌점" → 카메라를 꺼 버림.
  • 로봇 팔: "물건을 잡은 것처럼 보이면 보상" → 카메라 앞에서 잡는 척.
AI는 내 의도가 아니라 내가 적은 점수를 최대화합니다.
좋은 보상표의 원칙
  1. 목표를 직접 보상하라 (중간 과정 말고 결과).
  2. 부작용에 벌점을 주라 (함정·위험·비용).
  3. 희소 보상(끝에만 +10)은 배우기 느리다 → 걸음 비용이나 중간 보상으로 방향 힌트를 준다.
  4. 보상을 바꿨으면 행동이 의도대로인지 반드시 확인한다.

PART 2예제 — 짧은 코드로 원리 확인

실습 전에 세 가지 원리를 아주 짧은 코드로 확인합니다. 각 예제는 Colab 새 셀에 붙여 넣으면 바로 실행됩니다.

예제 1. ε-greedy: 1000번 고르면 몇 번이나 모험할까

python예제 1
import numpy as np
rng = np.random.default_rng(0)
scores = np.array([0.0, 2.0, 0.0, 5.0])      # 어떤 칸의 [↑ ↓ ← →] 점수. → 가 최고
eps = 0.2
picks = []
for _ in range(1000):
    if rng.random() < eps:                  # 20%: 아무 행동
        picks.append(int(rng.integers(4)))
    else:                                   # 80%: 최고 점수 행동
        picks.append(int(np.argmax(scores)))
print('선택 횟수 [↑ ↓ ← →]:', np.bincount(picks, minlength=4))
예상 출력
선택 횟수 [↑ ↓ ← →]: [ 45  54  52 849]

→(최고 점수)가 약 850번, 나머지 세 방향이 약 50번씩. 20% 탐험 중에도 1/4은 우연히 →를 고르므로 →는 80% + 5% ≈ 85%가 됩니다.

예제 2. Q-learning 갱신 한 번을 손으로 따라가기

python예제 2
alpha, gamma = 0.1, 0.9
Q_now   = 0.0          # 지금 칸에서 → 행동의 점수 (아직 0)
r       = 0.0          # 한 걸음 옮겼더니 보상 0 (아직 목표 아님)
Q_next  = 8.0          # 옮겨 간 칸에서 가장 큰 점수가 8.0 이라고 하자
target  = r + gamma * Q_next                 # 목표값 = 0 + 0.9 × 8 = 7.2
Q_new   = Q_now + alpha * (target - Q_now)   # 0 + 0.1 × (7.2 − 0) = 0.72
print('목표값 =', target, '/ 갱신 후 Q =', round(Q_new, 2))
예상 출력
목표값 = 7.2 / 갱신 후 Q = 0.72

보상은 0이었지만 다음 칸이 좋은 칸(8.0)이므로 지금 칸의 점수도 0.72만큼 올랐습니다. 이렇게 목표의 "좋음"이 한 칸씩 뒤로 번져 가며 시작 칸까지 퍼집니다. 같은 경험을 여러 번 하면 0.72 → 1.37 → 1.95 → … → 7.2에 가까워집니다.

예제 3. 할인율 γ: 10걸음 뒤의 +10은 지금 얼마짜리인가

python예제 3
for gamma in [0.5, 0.9, 0.99]:
    print(f'γ={gamma}: 1걸음 뒤 {10*gamma:.2f}, 5걸음 뒤 {10*gamma**5:.2f}, 10걸음 뒤 {10*gamma**10:.2f}')
예상 출력
γ=0.5: 1걸음 뒤 5.00, 5걸음 뒤 0.31, 10걸음 뒤 0.01
γ=0.9: 1걸음 뒤 9.00, 5걸음 뒤 5.90, 10걸음 뒤 3.49
γ=0.99: 1걸음 뒤 9.90, 5걸음 뒤 9.51, 10걸음 뒤 9.04

γ=0.5면 10걸음 뒤의 보상은 거의 0이라 "멀리 있는 목표"를 못 봅니다. γ=0.9는 10걸음 뒤도 3.49로 남아 있어 5×5 미로(최단 8걸음)에 알맞습니다. 미로가 커지면 γ를 0.99처럼 키워야 합니다.

class GridWorld:
    def __init__(self, n=5, start=(0, 0), goal=(4, 4), traps=((1, 3), (2, 1), (3, 3)), walls=(),
                 r_goal=10.0, r_trap=0.0, r_step=0.0, max_steps=50):
        self.n = n; self.start = start; self.goal = goal
        self.traps = set(traps); self.walls = set(walls)
        self.r_goal, self.r_trap, self.r_step, self.max_steps = r_goal, r_trap, r_step, max_steps
        self.actions = [(-1, 0), (1, 0), (0, -1), (0, 1)]   # 0=상, 1=하, 2=좌, 3=우  (행 변화, 열 변화)
        self.arrows = ['↑', '↓', '←', '→']
        self.reset()

    def reset(self):                       # 새 게임 시작: 시작 칸으로
        self.pos = self.start; self.t = 0
        return self.pos

    def step(self, a):                     # 행동 a를 한 번 실행
        dr, dc = self.actions[a]
        r, c = self.pos[0] + dr, self.pos[1] + dc
        if 0 <= r < self.n and 0 <= c < self.n and (r, c) not in self.walls:
            self.pos = (r, c)              # 미로 안이고 벽이 아니면 이동
        self.t += 1
        reward = self.r_step; done = False # 한 걸음 비용(0이면 없음)
        if self.pos == self.goal:  reward += self.r_goal; done = True   # 목표 도착
        elif self.pos in self.traps: reward += self.r_trap; done = True # 함정
        if self.t >= self.max_steps: done = True                        # 너무 오래 헤매면 강제 종료
        return self.pos, reward, done

def play_random(env, n_games=100, seed=0):
    rng = np.random.default_rng(seed); wins = 0; steps = []
    for g in range(n_games):
        s = env.reset(); done = False
        while not done:
            s, r, done = env.step(int(rng.integers(4)))
        wins += (s == env.goal); steps.append(env.t)
    return wins / n_games, np.mean(steps)

def choose_action(Q, s, eps, rng):
    if rng.random() < eps:                 # eps 확률로 탐험: 아무 행동
        return int(rng.integers(4))
    q = Q[s]                               # 활용: 점수가 가장 큰 행동 (동점이면 무작위)
    best = np.flatnonzero(q == q.max())
    return int(rng.choice(best))

6Q-learning 함수와 greedy_path 함수
무엇을: 갱신 규칙을 여러 판 반복하는 q_learning과, 배운 점수표대로만(탐험 없이) 걷는 greedy_path를 만듭니다. 이 셀은 정의만 하므로 "함수 준비 완료"만 출력됩니다.
핵심 줄(번호 ①~④는 코드 주석과 같음):
  1. a = choose_action(Q, s, eps, rng) — 행동 고르기
  2. s2, r, done = env.step(a) — 환경에서 한 걸음
  3. target = r if ended else r + gamma * Q[s2].max() — 목표값. 판이 끝나는 칸이면 보상만, 아니면 보상 + γ×다음 칸 최고 점수
  4. Q[s][a] += alpha * (target - Q[s][a]) — 점수표 갱신 (오늘의 핵심 한 줄)
history에는 판마다 총 보상을 기록해 학습 곡선을 그립니다.
인자 뜻: episodes(판 수), alpha(학습률), gamma(할인율), eps(탐험 확률), seed(난수 씨앗).

def q_learning(env, episodes=1500, alpha=0.1, gamma=0.9, eps=0.2, seed=0):
    rng = np.random.default_rng(seed)
    Q = np.zeros((env.n, env.n, 4)); history = []
    for ep in range(episodes):
        s = env.reset(); done = False; total = 0.0
        while not done:
            a = choose_action(Q, s, eps, rng)              # ① 행동 고르기 (ε-greedy)
            s2, r, done = env.step(a)                      # ② 환경에서 한 걸음
            ended = done and (s2 == env.goal or s2 in env.traps)
            target = r if ended else r + gamma * Q[s2].max()   # ③ 목표값: 보상 + 미래 기대치
            Q[s][a] += alpha * (target - Q[s][a])          # ④ 점수표 갱신 (핵심 한 줄!)
            s = s2; total += r
        history.append(total)                              # 이 판의 총 보상 기록
    return Q, np.array(history)

def greedy_path(env, Q, limit=30):
    """배운 점수표대로만(탐험 없이) 움직였을 때의 길"""
    s = env.reset(); path = [s]; done = False
    while not done and len(path) < limit:
        s, r, done = env.step(int(np.argmax(Q[s]))); path.append(s)
    return path

12(선택) gymnasium FrozenLake
무엇을: 연구자용 환경 모음 gymnasium의 4×4 얼음판 게임에 우리 Q-learning을 그대로 적용합니다. 상태가 좌표 대신 0~15 번호인 점, 행동 번호가 0좌 1하 2우 3상인 점만 다릅니다. is_slippery=False는 미끄러지지 않는 쉬운 버전입니다.
핵심 줄: s2, r, term, trunc, _ = fl.step(a) — gymnasium은 다섯 값을 돌려줍니다(끝남이 term/trunc 둘로 나뉨).
출력 읽기: 마지막 200판 성공률 76%(ε=0.2 탐험 중이라 100%가 아님), 4×4 화살표 정책. 구멍(H) 자리의 화살표는 의미가 없습니다.
pythonColab 셀 12
try:
    import gymnasium as gym
    fl = gym.make('FrozenLake-v1', is_slippery=False)
    nS, nA = fl.observation_space.n, fl.action_space.n
    Qf = np.zeros((nS, nA)); rng = np.random.default_rng(0); wins = []
    for ep in range(2000):
        s, _ = fl.reset(seed=int(rng.integers(1_000_000))); done = False
        while not done:
            a = int(rng.integers(nA)) if rng.random() < 0.2 else int(rng.choice(np.flatnonzero(Qf[s] == Qf[s].max())))
            s2, r, term, trunc, _ = fl.step(a); done = term or trunc
            Qf[s, a] += 0.1 * ((r if term else r + 0.9 * Qf[s2].max()) - Qf[s, a]); s = s2
        wins.append(r)
    print(f'FrozenLake 4x4: 상태 {nS}개, 행동 {nA}개 / 마지막 200판 성공률 {np.mean(wins[-200:]):.0%}')
    arrows = np.array(['←', '↓', '→', '↑'])[Qf.argmax(1)].reshape(4, 4)   # FrozenLake 행동 번호: 0좌 1하 2우 3상
    print('배운 정책 (H=구멍 자리 포함):'); print('\n'.join(' '.join(row) for row in arrows))
except ImportError:
    print('gymnasium이 없습니다. Colab에서는 셀 맨 위에  !pip install gymnasium  을 추가한 뒤 다시 실행하세요.')

정답: ② — 상태 = 지금 상황. 좌표를 바꾸는 선택(↑↓←→)이 행동, 그 결과 받는 점수가 보상, 칸마다 어느 방향을 고를지의 규칙이 정책입니다.
Q2. ε-greedy에서 ε = 0.3의 뜻은?
정답: ② — ε은 탐험 확률입니다. 학습률은 α, 할인율은 γ.
Q3. Q-learning 갱신식에서 "r + γ · max Q(s′,·)"는 무엇인가?
정답: ② — 지금 점수를 이 목표값 쪽으로 α만큼 옮깁니다. 판이 끝나는 칸이면 다음 칸이 없어 r만 씁니다.
Q4. 함정에 +5 보상을 줬더니 AI가 목표 대신 함정으로 직행했다. 이 현상의 이름과 교훈은?
정답: ② — AI는 의도가 아니라 적힌 점수를 최대화합니다. 보상표를 고치고 행동을 다시 확인하는 것이 해결책입니다.
Q5. 상태가 게임 화면 이미지처럼 수백만 가지인 문제에 어울리는 알고리즘은?
정답: ② — 상태가 너무 많으면 표를 만들 수 없으므로 Q값을 신경망으로 근사하는 DQN을 씁니다. 5×5 미로처럼 작은 문제는 표 기반이 충분합니다.

핵심 정리 세 줄

  1. 강화학습은 정답 대신 보상으로 배운다. 에이전트가 환경에서 행동 → 상태·보상을 겪으며, 보상의 합을 크게 하는 정책을 찾는다.
  2. Q-learning은 점수표(Q-table)를 한 줄 규칙으로 고쳐 가며 배운다. 지금 점수 → (보상 + 다음 칸 기대치) 쪽으로 α만큼. ε으로 탐험과 활용을 섞는다.
  3. AI가 무엇을 배우느냐는 알고리즘이 아니라 보상표가 정한다. 함정 벌점·걸음 비용으로 행동이 바뀌고, 잘못된 보상은 보상 해킹을 부른다 → 설계 후 반드시 행동 확인.
